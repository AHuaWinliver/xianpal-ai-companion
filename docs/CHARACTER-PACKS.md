# 0.5 角色资源包与热更新

安装支持本功能的 **0.5.0** 版本后，后续新增人物或更新人物不需要重新安装程序，也不需要在使用者电脑上编译。将完整资源包放进角色目录，运行中的程序会自动校验；新角色出现在“切换形象”中，当前选中角色的有效更新会直接应用。

这是本地、离线的**资源热更新**，不是联网下载或程序代码热更新。资源包不能包含 DLL、EXE、脚本或自定义执行命令。

## 给使用者：安装新人物

1. 右键宠物 → **切换形象 → 打开角色资源目录**。
2. 将制作方提供的完整人物文件夹复制进去，文件夹内应直接包含 `character.json` 及各动作目录，不要再多套一层压缩包目录。
3. 复制完成、文件停止变化约 1.5 秒后，程序会在后台校验；完成后重新展开“切换形象”，选择标有“外置”的新角色。大包的校验需要更多时间。
4. 若没有出现，选择 **刷新外置角色 / 查看校验结果**，按提示处理错误。

默认目录：`%LOCALAPPDATA%\XianPal\Characters`。它位于当前用户目录，不放在安装目录，不要求管理员权限，升级安装器不会清理该目录。需要自定义位置时可在启动前设置 `XIANPAL_CHARACTER_DIR`；路径不能经过符号链接或目录联接。

```text
Characters/
└── my-companion/
    ├── character.json
    ├── idle/00.png ... 07.png
    ├── waiting/00.png ... 07.png
    ├── failed/00.png ... 07.png
    ├── running/00.png ... 23.png
    ├── running-left/00.png ... 23.png
    ├── running-right/00.png ... 23.png
    ├── waving/00.png ... 23.png
    ├── review/00.png ... 23.png
    ├── jumping/00.png ... 23.png
    ├── punching/00.png ... 23.png
    ├── eating/00.png ... 23.png
    └── wiping-mouth/00.png ... 23.png
```

新角色不会自动抢占当前人物，需手动选择一次；以后更新同一个 `id` 的角色时，当前人物会自动刷新。新名字、人设、台词和提醒样式也随配置更新。

## 更新已有外置角色

- 从完整包中复制新的动作 PNG，**最后替换 `character.json`**。配置中的逐帧 SHA256 必须与图片一致；中途混合了新旧图片时会校验失败，保留当前已加载形象。
- 更稳妥的方式是在 `Characters/.upload/my-companion` 中准备完整新包，将旧目录移到 `.backup` 等点号开头目录，再把新人物文件夹移到 `Characters/my-companion`。扫描会忽略点号开头的暂存目录；移动期间尽量不要停顿。
- 不修改人物 `id` 来发布小更新；提高资源包 `version`，例如 `0.1.0` → `0.1.1`。程序按内容摘要识别变化，不仅比较版本数字。
- 已加载 PNG 不锁文件；可以覆盖源图片。更新会避开正在打开的菜单、拖动、吃文件和提醒演出，等这些交互结束后应用。
- 配置无效、缺帧、错误尺寸、哈希不匹配或图片损坏，都不替换当前已加载画面。首次加入的坏包不会出现。发现问题后修复文件即可重试，或使用手动刷新。
- 保留的是**进程内当前已加载的画面**，不是持久化的旧包副本。坏包在重启后不会加载；不要将其当作备份机制。保留一份原资源包方便恢复。
- 删除当前外置人物的目录后，会安全回退到内置青衡；其他内置人物不受影响。

无需重装不代表旧版二进制凭空获得该功能：首次仍需使用包含资源加载器的 0.5.0 程序，之后才是仅更新人物文件。

## 给制作者：配置与导出

先复制 [角色配置模板](templates/character-profile.json)，填写自己的人物信息。这是**导出输入模板**，尚未带校验清单，不能直接扔进角色目录作为完整包。

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 当前为 `1`，不支持的版本会拒绝加载 |
| `id` | 3–48 字符；小写字母开头，仅小写字母、数字、连字符；必须和人物文件夹同名 |
| `version` | 三段资源版本号，例如 `0.1.0`，与软件 0.5.0 版本独立 |
| `name` / `persona` | 展示名最多 20 字符；人设最多 4000 字符；不提供执行代码能力 |
| `quotes` | 5–50 条，每条 1–200 字符；需符合原创人设 |
| `canvasWidth` / `canvasHeight` | 固定 `384` / `416`，所有动作保持同样比例和画布 |
| `mouthX` / `mouthY` | 文件卡片进入嘴部的位置，画布归一化坐标，严格介于 0 与 1 |
| `reminderStyle` | `command` 御剑、`beam` 灵符、`warning` 草木、`stone` 墨涟，使用本角色自己的动作帧 |
| `files` | 导出器生成的 240 条“相对文件名 → SHA256”清单；请不要手工省略或随意修改 |

内置 ID `orbit`、`spark`、`moss`、`pippin` 及历史兼容 ID 被保留，不能用外置包覆盖。外置人物的名字、画风与体型不受这四个内置人物限制。

### 导出一份完整人物包

素材制作方需先把动作渲染为上述 12 个目录的 PNG。可以使用自己的绘图/动画工具，也可以扩展项目的原画渲染器后取其输出；**不能直接把分层原画或骨架 JSON 当作成品帧导入**。

在源码根目录运行（制作者需要 Windows/.NET Framework 编译器；接收成品包的使用者不需要）：

```powershell
# 把 ProfilePath 换成填写好的配置，FramesDirectory 指向已完成渲染的动作目录
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\ExportCharacterPack.ps1 `
  -FramesDirectory C:\my-art\rendered `
  -ProfilePath C:\my-art\character-profile.json `
  -OutputRoot C:\my-packs

# 单独检查成品包；不启动宠物，不调用 Claude，不执行资源包中的代码
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\ValidateCharacterPack.ps1 `
  -PackDirectory C:\my-packs\my-companion
```

导出器复制动作、计算逐帧摘要，使用与程序相同的校验器检查，再将完整目录发布到 `OutputRoot/<id>`。目标已存在时拒绝覆盖；请导出到新位置并审阅，再更新安装中的资源。导出失败的未发布草稿保留在提示的点号开头目录中，供制作者检查，不会被宠物扫描。

把成功导出的 `<id>` 整个目录压缩分享即可。包根目录可附 `README.md`、`LICENSE.txt`，其他文件或未知子目录会被拒绝；素材应附来源和可授权范围，不要分发未经授权的角色。

### 画面与动作要求

- 240 张 RGBA 透明 PNG（不接受索引色替代）；每张必须为 384×416，单张最多 2MB，每个人物包最多 64MB，配置文件最多 64KB，最多同时扫描 16 个非暂存人物目录。
- 三种行走目录各有 24 个不同图片摘要，不允许复制 8 帧凑成 24 帧。首尾无缝、对侧手脚协调、头身与脚底稳定，无裁切、实色背景或粉边。
- 外置人物使用**完整预渲染帧**，不套内置人物的颈根、五官和肢体参数。眨眼、嘴部变化应画进动作帧；当前不支持为任意外置头型动态叠加内置六张表情贴片。
- 全屏演出可在现有四种时间线中选择，人物会换成自己的帧，但不是任意新道具/时间线脚本热加载。御剑样式对脚底位置有要求，请实际预览再发布。
- 校验能检查结构、文件完整性、尺寸、格式与帧数，不能替代动作审美、真实透明效果及权利审核。制作规则见 [人物定制指南](CHARACTER-CUSTOMIZATION.md)。

## 开发与测试入口

`CharacterPackCatalog.cs` 负责数据格式、限制、哈希与独立图片验证；`PetForm.CharacterPacks.cs` 负责文件变更去抖、后台扫描、延迟应用和菜单；人物元数据由 `PetCharacter.Available` 提供。`PetCharacter.All` 仍只表示内置四角色，保持素材构建和内置测试兼容。

资源替换先完成校验和解码，再释放当前位图。外置人物原生帧缓存按需建立；退出/销毁时停止监听并释放等待交付的图像。不向安装目录、Claude 配置或用户文档写入人物数据。

```powershell
# 先执行 build.ps1，再运行完整的离线热更新测试
.\tests\character-pack-test.ps1
```

测试使用合成矩形素材与隔离状态，覆盖新增、切换、运行中更新、损坏保留、修复恢复、菜单避让、删除回退、资源释放及成品导出；不调用真实模型或修改真实开机启动项。
